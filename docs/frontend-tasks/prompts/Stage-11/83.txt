BỐI CẢNH:
Dự án Warehouse Management System, backend NestJS + Prisma. Model `Schedule` hiện chỉ có 1
`suggestedSlotId`/`actualSlotId` (single slot), nhưng khi số lượng nhập/xuất lớn, cần chia hàng vào nhiều
slot khác nhau. Cần thêm bảng quan hệ 1-n để lưu danh sách đầy đủ các vị trí/lô được gợi ý hoặc thực hiện
thực tế cho 1 lịch, mà KHÔNG xoá field `suggestedSlotId`/`actualSlotId`/`suggestedBatchId`/`actualBatchId`
hiện có (giữ lại làm "vị trí chính", bảng mới lưu toàn bộ danh sách).

MỤC TIÊU TASK (CHỈ LÀM ĐÚNG VIỆC NÀY):
1. Thêm enum `AllocationKind` gồm 2 giá trị: `SUGGESTED`, `ACTUAL`.
2. Thêm model `ScheduleAllocation` với các field:
   - id (uuid, primary key)
   - scheduleId (String, FK tới Schedule, onDelete: Cascade)
   - kind (AllocationKind)
   - slotId (String, FK tới Slot, bắt buộc)
   - batchId (String?, FK tới Batch, optional vì lúc gợi ý Inbound có thể chưa có batch thật)
   - quantity (Int)
   - sortOrder (Int, default 0) — thứ tự ưu tiên hiển thị
   - createdAt (DateTime, default now())
   - index trên (scheduleId, kind)
   - map tên bảng SQL là "schedule_allocations"
3. Thêm relation `allocations ScheduleAllocation[]` vào model `Schedule`.
4. Thêm relation ngược `scheduleAllocations ScheduleAllocation[]` vào model `Slot` VÀ model `Batch` (Prisma
   bắt buộc phải có đủ 2 chiều quan hệ, nếu không sẽ lỗi validate).

QUY TẮC BẮT BUỘC:
- KHÔNG xoá/đổi field nào đang tồn tại trên `Schedule`, `Slot`, `Batch`.
- `batchId` PHẢI optional (`String?`).
- Quan hệ `scheduleId -> Schedule` PHẢI có `onDelete: Cascade`.
- KHÔNG chạy migration, KHÔNG tạo file trong prisma/migrations/.
- KHÔNG đụng vào bất kỳ file `.ts` nào trong apps/backend/src.
